# ForecastLab 可靠性与可读推演验收

日期：2026-10-09。服务器：group8 自有工作区；分支 `feat/scenario-workspace-parallel`。

本轮按用户要求修复前次审查问题，并删除旧研究。保持“取得可追溯证据后继续推演、输出主观概率”的方向；没有把模型措辞审查重新设为阻断条件。

## 修复范围

- 统一情景模式生效规则，防止旧版二元/null 概率指令继续进入模型输入。
- 每个概率情景同时生成定义、判定条件、分配理由及证据/假设/模拟引用；概率范围与合计仍做本地校验。
- AI/LLM 等通用类别词不再仅因原文字面缺失而拒绝发现；原文、段落、具体主体和数字检查仍保留。
- 恢复运行时重新核对已保存原文、哈希、段落和引用，不再信任旧 `findings_validated` 标记。
- 在 group8 用户范围安装监督服务，分别探测 API、路由与四个模型进程；模型退出时恢复真正的模型进程。
- 健康检查区分配置存在与服务实际可用。搜索配置在真实请求前标为“待请求验证”，不把凭据存在当作成功。
- 增加运行取消；取消会关闭进行中的 HTTP 请求，总活动截止时间覆盖请求和重试。维护停止先取消并落盘再结束 API。
- 主体阶段最多四个真实主体并行，使用物理 GPU 4、5、6、7；大阶段仍按依赖顺序执行，不宣称单个生成快四倍。
- 完整展示证据 E、发现 F、假设 H、模拟 S 引用；后续研究保存父记录关联。
- HTML 导出包含情景定义、主体行动、状态变化、审查提示和保存的完整原文；无法取得完整快照时明确标注摘录。
- 历史列表改为分页摘要，进入记录后再取详情；前端异步请求核对当前页面，避免旧响应覆盖新研究。
- 问题分析不再把“给出概率/证据/判定条件”等研究输出反问用户，也不把任务要求当成背景事实。
- 已回答的澄清保留稳定编号和用户答案，不再被模型重置为 open；新的不同问题仍保持待回答。已确认范围传入证据评估与后续五类模型输入，并在阅读区显示。

## 推演展示

参考 Decitron 的主体—行动—轮次阅读方式，采用可读尺寸节点、长摘要、大阅读区和独立完整页面。节点展示阶段实际产物，读者可继续展开目标、资源、约束、行动理由、适用条件、状态变化、冲突与引用。没有为凑内容编造模型结果。

桌面默认 100%、窄屏默认 90%；保留右键拖动、滚轮缩放、左键选择和侧栏折叠。完整页面能返回对应节点。长文本已在桌面与 390px 窄屏验证。

## 历史清理与运行边界

用户授权删除后，清空了原来的 6 条研究、相关原文快照、旧报告静态资源及本地旧报告导出。没有删除 Git 历史和工程审查记录。后续新增的记录仅用于本轮验收。

所有模型容器均显式绑定物理 GPU 4–7，每个容器只见一个逻辑 GPU 0。未修改共享驱动、内核、全局 Docker 配置或其他账号的计算任务。

本轮曾发现四个模型容器被外部删除，来源未查明；镜像和权重仍在，已在授权范围重建并恢复健康。不能把这一事件归因于尚未验证的原因。

搜索继续依赖用户现有本地代理及 SSH 反向隧道，已修复失效隧道并加入 keepalive。健康页如实显示依赖状态。
