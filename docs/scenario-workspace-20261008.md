## 四卡服务

仅使用物理 GPU 4、5、6、7，各一份 BF16 Qwen3-8B、16,384 上下文。每个容器仅暴露一张物理卡，内部逻辑编号为 0。`18054/18055/18056/18057` 分别对应物理 4/5/6/7。模型路由仍使用原入口 `127.0.0.1:18048/v1`，每张卡最多一个生成请求，支持有界排队和断连释放。

启动和检查（服务器 group8）：

```sh
cd /home/group8/work/forecastlab-main
python3 deploy/group8_model_workers.py start
python3 deploy/group8_model_workers.py status
# 首次部署可复制 example 到 .forecastlab/model-router.json，权限设为 600。
bash deploy/model-router-control.sh start
bash deploy/model-router-control.sh status
bash deploy/server-control.sh status
```

配置通过同目录临时文件原子替换，路由自动重载。只能配置字面量 loopback 地址。HTTP 错误和发送后的超时不会自动转投另一个 worker；只有建立连接失败可以切换。勿增加 uvicorn worker 数，否则单卡并发限制将失效。勿在四个单卡模型运行时启动旧 TP4 容器。

原 TP4 容器保留为停止状态。回滚材料在上述验证目录的性能子目录，必须先确认没有研究和排队请求，再按自有进程控制脚本执行；不修改共享驱动或其他账号任务。

## 实测范围

同一模型、精度、上下文、thinking 配置，输出长度固定 256 token。长输入为 7,726 token；以下是微基准，不能外推所有完整报告的耗时。

| 配置 | 短输入四并发合计 | 长输入四并发合计 |
|---|---:|---:|
| 原 TP4 | 121.00 token/s | 超过 180 秒未返回首 token |
| 单 TP1 同卡批四请求 | 64.71 token/s | 17.08 token/s |
| 四份 TP1 分流 | 95.70 token/s | 39.99 token/s（25.606 秒） |

路由端再实测四请求共 25.615 秒、39.977 token/s，103 个健康采样确认四个 worker 同时各有一个生成，排队数为 0。

四份 TP1 解决了本次长输入并发停滞，并比同卡四请求吞吐提高 2.34 倍；短输入吞吐低于原 TP4。单请求长输入仍约 10 token/s，更长上下文完整结构化生成实测会进一步下降。因此没有声称单条生成速度提升四倍。
